# TypeScript + Vue: UI（UI の実装）

見た目の決定はプロジェクトの `DESIGN.md`（雛形は `project-bootstrap` の `templates/typescript-vue/project/DESIGN.md`）、レビューは `ui-review` スキル。調べた経緯と、入れなかったものの理由は `rationale/ui-standards.md`。

## UI-01 状態

- 一覧・詳細・フォームなど、データを読む画面ごとに「空」「読み込み中」「エラー」を作る。どれも presentation の分岐なので、分岐の多い部品は presentation のテストで3つとも描画する（TEST-05）
- 読み込み中は `QSkeleton` で、揃ったときと同じ寸法の骨格を出す（レイアウトが跳ねないように）。部分の再読み込みは `QInnerLoading`
- エラーは `QBanner` などで、何が起きたかと、次にできる操作（再試行など）を並べる。トーストだけで済ませない（消えると手がかりが残らない）
- 空の状態には、中身を作る操作への導線を置く。「データがありません」だけにしない
- 送信ボタンは送信が始まるまで押せるままにし、送信中は `loading` を付ける

## UI-02 キーボードとコントラスト

- Quasar の部品（`QBtn`・`QInput`・`QDialog` など）を優先して使う。`<div @click>` で操作を作らない。フォーカスの表示（`q-focus-helper`）を CSS で消さない
- アイコンだけの `QBtn` には `aria-label` を付ける。文言は翻訳キーで出す（I18N-01）
- 状態を色だけで伝えない。`positive`・`negative` などの色には、アイコンか文言を添える
- ドラッグでできる操作（並べ替え・移動）には、メニューやボタンでの別の手段を用意する（WCAG 2.2 の 2.5.7）
- コントラストは `DESIGN.md` に色の組み合わせとして書き、`ui-review` のスクリーンショットで確かめる。機械での検査は未導入（`rationale/ui-standards.md`）

## UI-03 値を役割の名前で参照する

`DESIGN.md` のトークンを、Quasar の仕組みに次のように写す。画面のコードは右の列だけを使う。

| `DESIGN.md` の項目         | 写す先                                                                                                 | 画面での使い方                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| 色（ブランド・意味の色）   | `src/css/quasar.variables.scss` の `$primary`〜`$warning`。実行時に変えるなら `framework.config.brand` | `color="primary"`、`text-negative`・`bg-positive` などのクラス |
| ダークの面                 | `$dark`・`$dark-page`、`framework.config.dark: 'auto'`                                                 | `body.body--dark` で切り分ける                                 |
| 余白                       | `$space-base`（xs・sm・md・lg・xl は Quasar が倍率で作る）                                             | `q-pa-md`・`q-gutter-sm` などのクラス                          |
| 文字の大きさと階層         | Quasar の文字のクラスを役割に割り当てる（`DESIGN.md` に対応を書く）                                    | `text-h6`・`text-subtitle2`・`text-caption` など               |
| 足りない値（角丸・影など） | `quasar.variables.scss` に変数を足す                                                                   | `<style scoped lang="scss">` で `$` の変数を参照する           |

- 色の値（`#…`・`rgb(…)`）と px の余白を `.vue` に直接書かない。`<style>` の中でも変数を使う
- **強制**: `style="…"` と、`:style` の固定値は共有設定の `vue/no-static-inline-styles` で落ちる（2026-11-16 に eslint-plugin-vue 9.33 で確認。`:style` の動的な値と、クラスは落ちない）。`<style>` の中の直書きは ESLint では検査できず、規約と `ui-review` で見る
- Quasar CLI は `<style lang="scss">` の中に `$` が1つでもあれば変数を読み込む。読み込まれないときは `// $` のコメントを足す（Quasar の文書のとおり）

## UI-04 描画して確かめる

- `ui-review` スキルを、実装したのとは別の文脈（新しいセッションか subagent）で使う。dev サーバー（`.claude/launch.json`）で画面を開き、幅 375・768・1280 のスクリーンショットと、UI-01 の3つの状態を見る
- 見た目の変更を含む PR は、確かめたスクリーンショットの幅と状態を本文に書く

## センス（見た目の方向）

検証できない領域なので原則にはせず、ここに既定の考え方を置く。プロジェクトの `DESIGN.md` に書いたことが優先する。Impeccable を Trial で試している（`radar/impeccable.md`）。結果によってこの節を直す。

- **業務の画面では、操作の形を標準から変えない。** ナビゲーション・ボタン・入力・表は Quasar の部品のまま使う。プロダクトらしさを出すのは、書体・配色・密度と、目立たせる表現1つまでにする
- **階層は大きさ・太さ・色の濃さで作る。** 強調したいものを増やすほど何も目立たなくなる。1つの領域で主要な操作は1つにし、`unelevated` の `primary` で示す。ほかは `flat` か `outline`
- **余白は関係を表す。** 関係の近いものは詰め、グループの階層が上がるほど広げる。値は Quasar の5段階から選ぶ。見出しの上は下より広くとる
- **意味のある色だけを使う。** `positive`・`negative`・`warning`・`info` は状態を伝えるときだけに使い、飾りに使わない。アクセントの色は少なく使う
- **入れ物で済ませない。** すべてを同じ大きさのカード（`QCard`）で並べない。カードの中にカードを入れない
- **飾りを足して整えない。** グラデーションの文字・装飾のぼかし・意味のない番号や上付きの小見出しは使わない。足す前に、余白・揃え・階層で解決できないかを見る
- **本物に近い内容で作る。** 仮の文言や「Lorem ipsum」で作らず、実際の長さ・件数・桁数で崩れないかを見る
