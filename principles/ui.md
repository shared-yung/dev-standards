# UI（UI）

画面を持つプロジェクトに適用する。見た目の好みは原則にせず、検証できる下限だけを置く。

### UI-01 画面ごとに空・読み込み・エラーの状態を作る〔標準〕

データが揃った状態だけを作らない。空の状態には、何をすれば中身が出るかを示す。

- 目的: 揃っていない画面は壊れて見え、利用者が次に何をすればよいか分からない

### UI-02 キーボードだけで操作でき、文字が読める〔標準〕

操作はキーボードでも行え、フォーカスが見え、文字と背景のコントラストは WCAG AA を満たす。ドラッグでできる操作には別の手段を用意する。

- 目的: 好みと違い検証できる下限なので、デザインの方針にかかわらず外さない

### UI-03 見た目の値は役割の名前で参照する〔標準〕

色・余白・文字の大きさは、プロジェクトのデザインの記録で役割の名前を付けて定義し、画面には値を直接書かない。

- 目的: 見た目の決定が1か所に残り、画面ごとにばらつかない

### UI-04 見た目は描画して確かめる〔標準〕

見た目の完成は、実際に描画した画面を複数の幅で見て判定する。判定は実装とは別の文脈で行う（AGENT-01）。

- 目的: 余白や階層の崩れはコードからは見えず、書いた本人には見落としやすい
