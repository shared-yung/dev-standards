# リポジトリ（REPO）

### REPO-01 改行コードは LF に統一し、リポジトリ側で強制する〔必須〕

リポジトリ内・作業ツリーとも LF。リポジトリの属性ファイルで強制し、各自の設定に依存させない（エディタや formatter の設定は補助）。新規リポジトリでは最初に置き、混ざったら正規化する。

- 目的: 誰がどの OS でクローンしても同じ内容になる

### REPO-02 設定・データファイルをスクリプトに埋め込まない〔必須〕

JSON / YAML などは別ファイルに置き、スクリプトは読み込むだけにする。外部へ送る前に構文を検証する。

- 目的: 埋め込むと formatter も構文チェックも効かず、実行するまで壊れていることに気づけない

### REPO-03 秘密情報をリポジトリに置かない〔必須〕

鍵・トークン・パスワードはコミットしない。環境変数ファイルは無視設定に入れ、例だけをコミットする。

- 目的: 履歴に入った秘密情報は取り戻せない

### REPO-04 モノレポの構成〔標準〕

ルートの1階層下にプロジェクトフォルダを作り、その中で初期化する。ルート直下にアプリのソースを置かない。プロジェクトをまたぐ共有コードは `packages/` の独立パッケージにする。

### REPO-05 ドキュメントの置き場〔標準〕

各プロジェクトの `docs/` に `spec/`（何を作るか）/ `architecture/`（どう作るか）/ `adr/`（なぜそう決めたか）。

### REPO-06 AI 向け指示ファイルの構成〔標準〕

ルートの指示ファイルは概要とインデックスに留め、詳細は作業の種類ごとに分けてリンクする。複数のエージェントから読めるよう、実体は1か所に置いて他方から参照させる。

- 目的: 常に読み込まれる量を抑え、エージェント間で内容が食い違わない

### REPO-07 CI の権限を絞り、取り込むコードを固定する〔必須〕

CI のジョブに渡す権限は必要な分だけを明示し、ジョブ内で動くコードに認証情報を残さない。外から取り込んで実行するもの（action・ツールの版）は付け替えられない参照に固定し、更新は差分を見て取り込む。

- 目的: 依存やツールが乗っ取られても取り込む前に気づけ、乗っ取られたコードにできることを限る
