# テスト（TEST）

### TEST-01 domain / use-case はテストを先に書く〔標準〕

t_wada 流の TDD（テストリスト → Red → Green → Refactor）。infrastructure / presentation は任意で、スパイクの後に書いてもよい（スパイクは捨てて TDD でやり直す）。

### TEST-02 バグ修正は再現テストから〔必須〕

層を問わず、再現テストを先に書く。書けない場合は PR に理由を書く。

- 目的: 直ったことと再発しないことを証明する

### TEST-03 テストを変えてよいのは実装の前だけ〔必須〕

仕様が変わった／仕様の理解が誤っていたときだけ。実装の後で通すために変えるのは禁止。refactor ではテストを変えない。

- 目的: テストを実装に合わせると、仕様の証明でなくなる

### TEST-04 AI エージェントの進め方〔標準〕

実装の前に、期待した理由で落ちた出力を示す。歩幅は明白な実装を基本にし、テストリストは1件ずつ進める。機械的には強制しない（squash で順序が消える）ので、既存テストを書き換えた瞬間にフックで注意を差し込む（ブロックはしない）。

### TEST-05 テストの厚さと実行のタイミング〔標準〕

domain / use-case を厚く、presentation は分岐の多いものだけ、infrastructure は通信を模擬して薄く。カバレッジ閾値は domain / use-case だけ。PR で型検査・lint・単体テスト、main へのマージ時に E2E。テストランナーは1つに絞る（E2E は別でよい）。
