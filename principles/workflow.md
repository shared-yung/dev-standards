# Git ワークフロー（WF）

### WF-01 作業は issue 起点〔必須〕

issue のない変更は入れない。例外は root commit のみ（ローカルの検査と CI の両方で除外する）。

- 目的: 変更の理由と計画を、変更より先に残す

### WF-02 ブランチの命名と main の保護〔標準〕

`<type>/<issue番号>-<slug>`（例 `feat/42-quiz-scoring`）。`main` への直 push は禁止。

### WF-03 コミット規約〔標準〕

Conventional Commits。フッターに `Refs: #<issue番号>` を必須にし、scope は feature 名に合わせる。

### WF-04 PR の規約〔標準〕

`Closes #<issue番号>` で issue にリンクし、squash merge する。PR タイトルもコミット規約に従う（squash でコミット件名になる）。

### WF-05 計画との差異を記録する〔必須〕

PR 本文に「計画との差異」節を必須にし、空欄は CI で落とす（差異が無ければ「なし」）。マージ時にリンク先 issue へ自動でコメントする。

- 目的: issue は着手前の計画。方針が変わるのは正常で、**記録が残らないことが問題**

### WF-06 マージ後のブランチは自動で消す〔標準〕

リモートはマージ時に自動削除、ローカルは取り込み後にスクリプトで消す。squash merge では通常の削除が効かないので、消してよい条件を判定して強制削除する。手で強制削除しない。

### WF-07 規約の強制は3層で行う〔必須〕

ローカルの git hook → CI（コミット・ブランチ名・linked issue・計画との差異）→ ブランチ保護の required status checks。

- 目的: ローカルの検査は迂回できる。実効的な境界はブランチ保護にしかない
