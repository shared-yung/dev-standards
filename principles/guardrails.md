# リモート操作のガードレール（GR）

### GR-01 リモートに影響する操作は実行前に承認を得る〔必須〕

GitHub リモートに影響する操作（push、`gh` の変更系、`gh api` の書き込み）は、AI エージェントが実行する前にユーザーの承認を得る。読み取り系は承認不要。

- 目的: 外部に出た変更は取り消しにくい

### GR-02 マージ・強制 push・リポジトリ削除はエージェントに許さない〔必須〕

PR のマージは人間だけが行う（エージェントの設定で deny）。`git push --force` とリポジトリの削除も deny。

- 目的: 承認プロンプトには差分が出ず、レビューの代わりにならない。マージは差分と CI を見て人間が決める

### GR-03 ガードレールも多層にし、迂回不能な層を持つ〔必須〕

エージェントの permission 設定 → コマンド文字列全体を走査するフック → ホスティング側のブランチ保護。迂回不能なのは最後の層だけ。permission ルールは前方一致でしか判定できず `cd x && gh issue create` のような複合コマンドを取りこぼすので、フックで補う。

- 目的: 設定やフックは無効化・迂回されうる。最後の砦を設定の外に持つ

### GR-04 リモート操作の承認は作業の区切りごとにまとめる〔標準〕

互いに依存しない作業は並列に進め、ローカルの編集・テスト・コミットまでは承認を待たずに進める。リモート操作は作業の区切りごとに一覧にして示し、1回の承認でまとめて実行する。一覧に無い操作は実行しない。作業の前提になるリモート操作は先に承認を取り、push の後に分かったこと（CI の結果）で直したら、改めてまとめて承認を取る。GR-01 の承認を省くものではなく、承認の単位を変えるだけ。計画の承認はこの対象ではない。

- 目的: GR-01 の安全を保ったまま承認待ちで止まる回数を減らし、外に出るものを一度に見渡せるようにする
