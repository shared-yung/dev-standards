# アーキテクチャ（ARCH）

### ARCH-01 オニオンアーキテクチャ〔標準〕

依存の向きは外側 → 内側の一方向。

- 目的: ビジネスロジックを UI・通信・保存の都合から切り離し、単体で検証・置き換えできる
- 適合性: 使い捨てのスクリプトや単一処理の小さな CLI では、層を分ける費用が利得を上回ることがある

### ARCH-02 feature-first〔標準〕

`features/<feature>/` の下に `domain/` `use-case/` `infrastructure/` `presentation/`（中身の無い層は作らない）。feature をまたぐ共有コードは shared / core に分離し、feature をまたぐ参照は公開 API（ARCH-07 の入口）経由のみ。

- 目的: 機能単位で変更・削除でき、機能間の結合が公開 API に限られる
- 適合性: パッケージ＝ディレクトリの慣習が強い言語（例: Go）では、慣習に合わせて切り方を調整してよい

### ARCH-03 依存の向きは機械的に強制する〔標準〕

層と feature の依存規則は、レビューではなく機械で検査する。

- 目的: 規約だけでは破られる。破った瞬間に落ちる仕組みが要る
- 適合性: パッケージ・プロジェクトの参照関係や可視性（例: Go の `internal/`、.NET のプロジェクト参照）で強制できるなら、静的解析より優先する

### ARCH-04 domain の外部依存は許可リストで最小限に〔標準〕

domain が依存してよい外部ライブラリはスキーマ／検証のための最小限。UI フレームワーク・状態管理・HTTP クライアント・日付ライブラリは禁止。禁止リストではなく**許可リスト**で管理する。

- 目的: domain をフレームワークの寿命から独立させる。禁止リストは新しく入ったライブラリを取りこぼす

### ARCH-05 外部の型は外側に閉じる〔標準〕

API 仕様などから生成した型・クライアントは infrastructure だけで使い、domain の型へ写す。生成物はコミットし、CI で再生成して差分が出たら落とす。

- 目的: 外部の変更を domain に波及させず、生成物の更新漏れも検出する

### ARCH-06 実行時検証は境界だけ〔標準〕

実行時の検証スキーマは、必要な境界（外部入力・外部 API の応答など）だけに手書きする。全エンドポイントに二重定義しない。

### ARCH-07 要素ごとに入口を1つ置く〔標準〕

要素（feature 直下・feature の各層・shared のモジュール）ごとに入口を1つ置き、**他の要素からは入口だけを参照する**。入口には名前を明示した再公開だけを書く（ワイルドカードの再公開と実装は置かない）。同じ要素の中では入口を経由しない。自分の入口は参照しない。テストは内部も検証するので対象外。

- 目的: 入口が公開 API の契約になり、公開面の変化が差分で見える。入口に実装を置くと循環の温床になる

### ARCH-08 import は依存先を名指しする〔標準〕

ディレクトリの外へ出る import は、ルートからの名前で依存先の要素を名指しする。相対パスは同じディレクトリ以下のファイルを直接指すときだけ。

- 目的: 依存の向きが import の行だけで読める。「何階層まで」で線を引くと、1階層で層をまたぐものを見逃す

### ARCH-09 実行時に残る import の循環を禁止する〔標準〕

型だけの循環（実行時に消えるもの）は対象外。

- 目的: 初期化前の値を参照する実行時エラーは、循環しているときにだけ起きる

### ARCH-10 実装の選択は合成ルートに閉じる〔標準〕

どの実装を使うか（設定値を含む）は feature ごとの組み立てに閉じ、起動処理は組み立てを呼ぶだけにする。feature の入口から出すのは、組み立て・画面の部品・他 feature が依存する port と型だけ。

- 目的: 実装の差し替えが1か所で済み、利用側が具体的な実装に依存しない

### ARCH-11 DI のキーを公開しない〔標準〕

注入キーは定義したファイルに閉じ、提供する関数と取り出す関数だけを公開する。取り出す関数は未提供なら例外を投げる（呼び出し側で検査しない）。提供する型は port。

- 目的: キーを持てば誰でも別の値を差し込める。port にすれば実装を替えても名前が変わらない

### ARCH-12 UI の状態ストアにロジックを持たせない〔標準〕

UI の状態ストアは presentation に置き、状態の保持と use-case の呼び出しだけを行う。
