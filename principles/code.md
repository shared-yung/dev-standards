# コード（CODE）

### CODE-01 閉じた値の集合には名前を付ける〔標準〕

enum に相当する値の集合は1か所で定義し、型も同じ定義から導く。分岐に使う値（判別子など）も対象で、値を直接書かない。外部ライブラリの値の集合は直接比べず、漏れと余計なキーが型検査で落ちる対応表で自分の定義に写す。

- 目的: 綴り間違いと、集合を変えたときの修正漏れを機械で検出する
- 適合性: ネイティブの enum が型安全で網羅検査も効く言語では、それを使う

### CODE-02 分岐は網羅的にし、漏れを型で落とす〔標準〕

閉じた集合で分岐するときは、どれにも当たらない場合を必ず書き、そこで「到達しない」ことを型で表す。網羅検査を外す抑制はしない。

- 目的: 値を足したときに、対応していない分岐がコンパイル時に分かる

### CODE-03 「値が無い」の表現を1つにする〔標準〕

言語ごとに1つに決め、比較の書き方も1つにする。外部ライブラリが別の表現を返す箇所だけ、理由つきで例外にする。

- 目的: 表現が混ざると、片方だけを検査する漏れが起きる

### CODE-04 省略可能な値の書き方を書き手に委ねない〔標準〕

書き方を1つに決めて機械で強制する。「指定しなかった」と「明示的に空」を区別したいものだけ理由つきで例外にする。「値が無い」を落とすだけの汎用ユーティリティは作らない。

- 目的: 書き分けを人に委ねると迷い、呼び出し側の回避策が増える

### CODE-05 生成関数とフレームワーク依存の関数を名前で分ける〔標準〕

フレームワークの実行時 API（リアクティビティ・ライフサイクル・DI など）を1つでも使うかだけで判断し、名前で区別する。依存は「フレームワーク依存 → 生成」の一方向。純粋な計算は動詞で始まる普通の関数にする。生成関数は依存を1つのオブジェクト引数で受け取り、戻り値の型を公開し、**モジュールの最上位でインスタンスを作らない**（いくつ作るかは合成ルートが決める）。生成時は配線だけ。フレームワーク依存の関数は許された文脈でだけ呼び、ロジックを持たず、サービスは DI で受け取る。強制は名前より境界（フレームワークに依存しない層での import 禁止）に寄せる。

- 目的: 名前から呼べる場所が分かり、文脈の外で呼んで黙って効かない誤りを防ぐ

### CODE-06 検査の抑制は最小範囲で、理由を必ず書く〔必須〕

lint・型検査の抑制は行単位にし、理由を書く。理由の無い抑制と使われていない抑制は検査で落とす。抑制の前に、抑制せずに済む書き方を探す。

- 目的: 理由が残らないと、外してよいかを誰も判断できない

### CODE-07 結果が環境や時間で変わる入力は port で受け取る〔標準〕

現在時刻の取得と時間の経過待ちは直接呼ばず、port として受け取る（実装の選択は ARCH-10）。線引きは結果が決定的でないかで、プラットフォームの API かどうかではない（寿命は決定的なので対象外）。計算の入力として渡される時刻も対象外。時計とタイマーは1つの port にまとめる。

- 目的: 時間に依存する振る舞いを、実時間を待たず決定的にテストする

### CODE-08 資源を持つ生成物の後始末は、性質を仕組みで保証する〔標準〕

後始末（dispose）は冪等にする。破棄は一方向で、破棄後の操作は受け付けない（テストで確かめる）。後始末は寿命に登録して一括で行い、順序は登録の逆順。途中の例外は握りつぶさず、残りを行ってから呼び出し側に返す。破棄したかを再代入できる値で持たない。業務の状態で一方向に変わるもの（ゲームの終了など）は対象外で、状態機械の状態として表す。

- 目的: 二重解放・解除漏れ・書き戻しを、書き手の注意ではなく仕組みで防ぐ
