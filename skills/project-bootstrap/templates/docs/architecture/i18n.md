# i18n の方針

**文言をハードコードしない。** 表示文字列はすべてロケールファイル経由にする。

## 置き場所

```
__PROJECT__/src/shared/i18n/
├── ja.ts                       日本語。これが型のマスター
├── en.ts                       英語。ja と同じ構造であることを型で保証
├── message-schema.ts           MessageSchema / MessageKey（ja の構造から導出する型）
├── messages.ts                 messages / Locale / DEFAULT_LOCALE
├── vue-i18n-augmentation.d.ts  vue-i18n の DefineLocaleMessage の型拡張
├── index.ts                    入口。上の公開するものを名前で再 export するだけ
└── use-app-i18n.ts             キーを型で縛った useI18n のラッパー
```

Quasar 標準の `src/i18n/` ではなく `src/shared/` の下に置いている。**feature をまたいで使う共有コード**であり、`shared` は境界定義で既に要素として登録されているため（[層構成](onion-layers.md)）。`src/i18n/` に置くと ESLint の boundaries に未知の要素として扱われ、設定の変更が必要になる。

ただし `shared/i18n/` は Vue に依存する（`useAppI18n` が vue-i18n を使う）ので、**境界上は `shared` ではなく `shared-ui` として扱う。** import できるのは presentation と合成ルートだけで、domain / use-case からは使えない（[ファクトリー関数とコンポーザブル](factories-and-composables.md)）。

登録は `src/boot/i18n.ts`（アプリ組み立て層）で行う。

## コンポーネントでは useI18n ではなく useAppI18n を使う

```ts
import { useAppI18n } from '@/shared/i18n';

const { t } = useAppI18n();
```

**理由: vue-i18n の `t` は未知のキーをコンパイルエラーにしない。**

vue-i18n の型は次のシグネチャになっている。

```ts
<Key extends string>(key: Key | ResourceKeys | number): string;
```

`Key extends string` があるため任意の文字列が通る。`DefineLocaleMessage` の型拡張は IDE の補完には効くが、**誤ったキーを検出しない**。ライブラリ側の設計であり設定の問題ではない。

`useAppI18n` は `t` を `MessageKey`（`ja.ts` から導出したドット区切りのキー）に絞ったラッパーを返す。これにより存在しないキーと階層違いのキーが `bun run typecheck` で落ちる。テンプレート内の `{{ t('...') }}` も vue-tsc が検査する。

## キーの命名と分割

### 名前空間

トップレベルは次のいずれかにする。

| 名前空間                          | 用途                                                     |
| --------------------------------- | -------------------------------------------------------- |
| `app`                             | アプリ全体の文言（タイトルなど）                         |
| `common`                          | **本当に文脈非依存の原子**のみ。OK / キャンセル / 閉じる |
| `error`                           | 汎用のエラー表示                                         |
| feature 名（`quiz` `room` `net`） | その feature の文言                                      |

feature のメッセージも `shared/i18n/` に置く。feature 配下に置くと、`shared` は `shared` しか import できない境界規則（[層構成](onion-layers.md)）に阻まれ、`useAppI18n` が全キーの型を知れなくなるため。**物理的な配置より名前空間の規律のほうが重要**という判断。

### 同じ文言だからという理由で共有しない

**これが最も重要なルール。** 重複を許容する。

日本語で同じ文字列でも、他言語では訳し分けが必要になることがある。"Close" が動詞か名詞か、丁寧度、UI の文字数制限。いったん共有してしまうと、後から片方だけ変えることができない。

```ts
// NG: 同じ「はい」だからという理由で共有する
common: { yes: 'はい' }

// OK: 使われる場所ごとに持つ
quiz: { judgeDialog: { correct: '正解' } },
room: { leaveConfirm: { confirm: '退出する' } },
```

共有してよいのは `common` に置く数個の原子だけ。**`common` が育ち始めたら境界が引けていないサイン**なので、feature 名前空間へ移す。

### キーは「文言」ではなく「使われる場所」で名付ける

```ts
// NG: 文言そのものが名前になっている。文言を変えるとキーが嘘になる
quiz: {
  pressButtonToAnswer: '...';
}

// OK: 場所で名付ける
quiz: {
  buzzerButton: {
    label: '...';
  }
}
```

### 文を断片から組み立てない

語順は言語によって違う。連結すると翻訳不能になる。

```ts
// NG
quiz: { remaining: '残り', seconds: '秒' }   // t('quiz.remaining') + n + t('quiz.seconds')

// OK: 完全な文 + 名前付き補間
quiz: { remainingSeconds: '残り {count} 秒' }
```

複数形もキーを分けず、vue-i18n のプルーラライゼーションを使う。

### 何が検出できて、何ができないか

| 問題                               | 検出                                                                          |
| ---------------------------------- | ----------------------------------------------------------------------------- |
| 翻訳漏れ（他ロケールでのキー不足） | **型で検出**（`ja.ts` がマスター。不足すると `TS2741`）                       |
| 存在しないキーの使用               | **型で検出**（`useAppI18n` の `MessageKey`。テンプレート内も vue-tsc が見る） |
| テンプレートのベタ書き文言         | **ESLint で検出**（`@intlify/vue-i18n/no-raw-text`）                          |
| **未使用キー**                     | **検出できない**。ロケールを `.ts` で持っているため公式プラグインが読めない   |
| 同一文言の重複                     | 検出しない。**意図的な重複が正常**なため                                      |

未使用キーが検出できないことは意識的なトレードオフ。ADR に再検討のトリガーを書いてある。

### ファイルが大きくなったら

1ファイルが読みづらくなったら `shared/i18n/<locale>/<namespace>.ts` に分割して `<locale>.ts`（例: `ja.ts`）で束ねる。サブフォルダに入口（`index.ts`）は置かない（[モジュールの入口](module-entry.md)）。今の規模では不要。

## ロケールを追加する

1. `ja.ts` と同じ構造で新しいファイルを作る。型注釈に `MessageSchema` を付けると構造のずれがコンパイルエラーになる
2. `messages.ts` の `Locale` と `messages` に追加する

`ja.ts` にキーを足すと、他のロケールで不足しているキーが型エラーになる。翻訳漏れが検出される仕組み。
