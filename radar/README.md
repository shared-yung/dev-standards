# Technology Radar

使い慣れた標準（Adopt）を既定にしつつ、新しい手法を安全に試し、その知見で標準を磨くための記録。ThoughtWorks の Technology Radar の段階を使う。

| 段階   | 意味                                            | 使ってよい場所                         |
| ------ | ----------------------------------------------- | -------------------------------------- |
| Adopt  | 標準。`principles/` と `stacks/` に書かれている | すべてのプロジェクト                   |
| Trial  | 実験中。仮説と評価基準を持って試す              | Trial を宣言したプロジェクトだけ       |
| Assess | 調べている段階                                  | スパイクだけ（本番のコードに入れない） |
| Hold   | 新しく使わない                                  | —                                      |

## ファイルの書式

手法ごとに1ファイル（`radar/<手法>.md`）。フロントマター:

```yaml
status: Trial # Adopt / Trial / Assess / Hold
replaces: [ARCH-02] # Trial: 置き換える〔標準〕の原則 ID（新しいスタックの追加なら空）
experiment: experiments/2026-10-python-uv-stack.md # Trial では必須
revisit-when: JS プラグインが stable かつ Vue 対応 # Hold では必須（Assess でも推奨）
```

本文: 何か・なぜその段階か・根拠へのリンク。`scripts/check.ts` が書式を検査する。

## 手順

1. **登録（Assess / Trial）**: issue を起こし、radar のファイルを作る。Trial なら `experiments/_template.md` をコピーして、仮説・対象プロジェクト・置き換える原則・成功／失敗の基準・振り返りの期日を書く
   - 置き換えてよいのは〔標準〕の原則だけ。〔必須〕は実験でも外さない
   - 1プロジェクトで同時に試すのは1〜2個まで（多いと結果の原因が分からない）
2. **宣言**: 対象プロジェクトの CLAUDE.md に `Trial: <手法>（置き換える原則: <ID>）` と書く
3. **観察**: 実装中に気づいたことを実験ファイルの「観察」に日付つきで追記する
4. **振り返り**（期日、またはプロジェクト終了時）: 次のどれかを決め、実験ファイルの「振り返り」に書く。結果にかかわらず知見は残す
   - **Adopt**: `principles/` か `stacks/` を更新する PR を出す。標準の弱点が分かったら、それも原則に反映する
   - **Trial 継続**: 期日を延ばし、別のプロジェクトでも試す
   - **Hold**: 理由と `revisit-when` を書く
5. **見直し**: Hold と Assess の `revisit-when` を定期的に確かめる
