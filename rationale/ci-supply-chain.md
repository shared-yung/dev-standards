# CI のサプライチェーン対策（REPO-07）の根拠

2026-10-28 に、CI の雛形を固めたときの記録（#58）。

## 何から守るか

CI のジョブでは、自分たちが書いていないコード（action・依存・ツール）が動く。どれかが乗っ取られると、そのコードはジョブのトークンと、ジョブに渡した secrets を使える。2025-03 の tj-actions/changed-files では、既存のタグが悪意のあるコミットに付け替えられ、タグで参照していたリポジトリの CI のログに secrets が出た。

2026-10 時点の dev-standards と配布先（quiz-match など）の被害の範囲は小さい。

- public で、Actions の既定のトークン権限は read
- CI は `pull_request` で起動し、secrets を使わない（fork からの PR のトークンは読み取り専用）
- bun は依存の lifecycle スクリプトを既定で止める（`docs/tooling/eslint-boundaries.md`）

ただし雛形は private リポジトリや secrets を使う CI にも流用される。この前提に頼らず、雛形の側で次を固める。

| 対策                                     | 防ぐもの                                                                                                                         |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| トップレベルの `permissions` を明示      | リポジトリ設定が write に変わったとき、または private で既定が write のとき、全ジョブに書き込み権限が渡る                        |
| checkout の `persist-credentials: false` | ジョブ内で動くコード（依存・ビルド・テスト）が `.git/config` からトークンを読む。どのワークフローも push しない                  |
| action をコミット SHA に固定             | タグの付け替え。SHA は付け替えられない。行末の `# vX.Y.Z` で版を読めるようにする                                                 |
| bun・uv の版を固定                       | `latest` は実行のたびに版が変わり、供給元の変化をそのまま取り込む。結果の再現性も失う                                            |
| PR の作成者が決める値を `env` で渡す     | `${{ github.head_ref }}` をシェルに直接埋め込むと、`$(...)` を含むブランチ名でコマンドを差し込める（スクリプトインジェクション） |

GitHub 自身の action（`actions/*`）も SHA に固定する。乗っ取りの可能性はプラットフォームと同じだが、全 action を同じ規則にしたほうがテストで強制しやすく、更新の手間も変わらない。

## Dependabot を使わない理由

Dependabot の `github-actions` は SHA の固定と組み合わせるのが定番だが、ここでは合わない。

- 雛形は `skills/project-bootstrap/templates/` の下にあり、`.github/workflows/` ではないので Dependabot が見ない
- 配布先の `conventions.yml`・`pr-merged.yml` は `sync-repo` の管理ファイル。配布先で版を上げても次の `sync-repo` で戻り、`--check` も差分を出す
- Dependabot の PR には issue が無く、ブランチ名（`dependabot/...`）とコミット（`Refs:` が無い）が WF-01〜03 の検査で落ちる。例外を足すと、issue 起点の規約に穴が開く

代わりに、dev-standards で issue を立てて版を上げ、管理ファイルは `sync-repo` で配る（手順は `stacks/github-workflow/00-index.md`）。版の更新が差分を読む人の手を通るので、REPO-07 の「更新は差分を見て取り込む」にも沿う。脆弱性のある版は Dependabot alerts（PR を作らない）で知る。更新の頻度が問題になったら、`gh api` でタグから SHA を引いて書き換えるスクリプトを足す。

## 外への通信の制限（Hold）

step-security/harden-runner のように、ジョブからの外への通信を許可リストで止める仕組みは採らない（Hold）。判断材料:

| 観点           | 内容                                                                                                                                                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 防げるもの     | 乗っ取られたコードが、盗んだものを外へ送ること。送り先に届かなければ secrets やトークンは漏れない                                                                                                                           |
| 今の利得       | 小さい。盗む価値のあるもの（secrets・書き込みトークン）がジョブに無い。上の対策で残るのは read のトークン（public なら誰でも読める内容）だけ                                                                                |
| 費用（運用）   | ジョブごとに許可する通信先を保つ。bun・npm のレジストリ、GitHub、Playwright のブラウザの配布元、PyPI、uv の配布元など。依存やツールを変えるたびに監査モードで観測し直し、足し忘れると CI が落ち、必須チェックが不安定になる |
| 費用（信頼）   | それ自体が sudo 権限でランナーに入る第三者の action。乗っ取られたときの影響は他の action より大きい                                                                                                                         |
| 費用（契約）   | 無料の範囲と有料の計画の境目は導入時に確かめる（2026-10 時点で未確認）。観測結果は StepSecurity のサービスに送られる                                                                                                        |
| 代わりになる手 | secrets を使うジョブを分け、`pull_request` で起動するジョブに secrets を渡さない（今の雛形の形）                                                                                                                            |

再検討のトリガー: CI で secrets を使う（デプロイ・公開・外部サービスの鍵）、書き込みトークンが要るジョブを増やす、private リポジトリで雛形を使う、のいずれか。そのときは、まずそのジョブに限って監査モードで入れ、通信先を観測してから止める。
